# Antislop delivery gate: phase 3 learning map and records

Date: 2026-11-23. Mode: during, explicit session override. Feature base d0e3387.
Scope: teach-v3.js, teaching.css, records.js, records.css; related test/docs only.
This is a scoped delivery report, not a certification of untouched site behavior.

Design read: Persian mathematical workshop for students, connected APOS path plus honest
attempt ledger. ENERGY 3 / RHYTHM 2 / MOTION 2. Current evidence workspace is focal; path
connects real prerequisites, not a second graph editor. Attempts carry real recordedAt,
training completion does not. Existing graph component/adapters and five tabs unchanged.

## Decisions and purpose

- Existing garden/coral and charcoal/turquoise tokens preserve identity and measured contrast.
- Vazirmatn stays local for Persian legibility; math remains existing KaTeX LTR.
- Horizontal lesson path becomes vertical on phones so DOM reading order matches layout.
- Circle numbers, square checks and dashed minus marks pair with text to distinguish status.
- Native ordered steps place current activity and fresh-exit requirement before the workspace.
- Matte sheet behind the path and record groups protects reading over the approved background.
- Timeline has a thin connecting rule to express actual chronology, no invented training dates.
- Overview and ledger have different compositions because completion and attempts differ.
- Management remains visible, with inline confirmation; no new modal or hidden reset action.
- Finite connection opacity feedback only reflects successful prerequisite completion. State is
  committed first; shared motion utility cancels it and low/reduced modes skip it.
- No new image, logo, font, icon library, navigation destination, glass or glow introduced.

## Recorded actions

- Lesson/unit buttons -> actual lesson/unit and heading focus, denied locked hash.
- Activity steps/continue -> existing full learning browser310 validates all32 actual activities,
  prediction-before-reveal,8 independent exits, manual continue and no stored answers.
- Completed current step -> label updates without requiring navigation; stable route focus across save.
- Details summary Space/Enter -> real saved answer/archive; open answer remains open on refresh.
- Filter keyboard -> native select value and explicit filtered empty state.
- Delete -> preview/cancel exact bytes, confirm only selected attempt, training unchanged.
- Import -> preview no write, cancel exact bytes, confirm valid distinct attempt, malformed JSON error.
- Retry/reload -> quota recovery and conflict recovery with existing inline confirmation.
- Reset -> active progress zero, archive and sessions retained.
- Migration -> cancel exact bytes, confirm archive but no fresh credit; consumed deleted turn persists.
- Motion -> new connection trace finite, immediate unlock, off cancellation, low/reduce skip.

## Limitations and remaining recommendation

The final unchanged review validator has 741/741 passing assertions and zero runtime
exceptions. Baseline and diagnostic runs showed one intermittent failure: abrupt reduced-motion change does not immediately
cancel one 240ms `.vertex-paint` Web Animation in the shared component. A diagnostic rerun
confirmed its target and duration. Fixing this requires shared engine work outside phase3;
no test was weakened and no global workaround was installed in teaching. A later green
run is not evidence this shared behavior was fixed. All seven final commands passed2167
assertions, including160 new feature checks.

No physical phone, hardware GPU, screen-reader speech, other browser engine or native browser
200% zoom tested; 200% text simulation and viewport reflow are explicit substitutes, not claims.
No further visual correction is recommended inside phase3 after screenshot review. A separate
technical review of shared vertex animation cancellation/timing is recommended. Do not start it or
phase4 automatically. PR remains for human review and is not merged.
