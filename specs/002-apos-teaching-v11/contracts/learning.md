# قرارداد آموزش و سازگاری داده؛ نسخهٔ ۱.۱

وضعیت: قرارداد پیشنهادی برای پیاده‌سازی پس از بازبینی فاز۱؛ فایل‌های runtime هنوز تغییر نکرده‌اند.

## محتوا و هویت

- productVersion=1.1، bankVersion=1.4 و curriculumVersion=3 مستقل‌اند.
- curriculum دارای lessons و units و activities است. unit.idها L1-Action تا L2-Schema
  هستند؛ stageId فقط یکی از چهار ساختار، lessonId فقط lesson1/lesson2 است.
- هر unit شامل objective، prerequisites، scaffolding، misconceptions، evidenceCriteria،
  requiredActivityIds، exitActivityId و progressWeight=1 است. هشت وزن مثبت؛ مجموع۸.
- هر activity شامل context با scenario/vertexMeaning/edgeMeaning/goal، cognitiveOperation،
  instructionSteps، parts، hints، explanation، rubric و sourceReferences است.
- sourceReferences شامل bankVersion/questionId، use=adapted یا direct، adaptationReason
  و originalAposStage است. direct از قرارداد اصلی پیروی می‌کند؛ adapted شناسهٔ آموزشی مستقل دارد.
- blueprint طراحی فایل runtime نیست؛ content/teaching.json فقط پس از کامل‌بودن همهٔ واحدها
  فعال شود. legacy content/teaching-v2.json snapshot دقیق فعلی است و بازنویسی نمی‌شود.

## شواهد و ارزیابی

نوع پاسخ‌ها باید در محتوا قابل انتخاب و در اعتبارسنجی allowlist شوند:

| نوع | بررسی خودکار | نمایش و بازاندیشی |
| --- | --- | --- |
| relation/model | دو سر، جهت، چندگانگی و نگاشت مطابق قرارداد مسئله | جدول رابطه و خطای مشخص |
| neighborhood/coverageTable | مجموعهٔ همسایه و خود رأس، برای هر رأس یک شاهد معتبر | مرکز/پوشیده/بی‌پوشش هم با متن هم رنگ |
| deletionTable | حذف مستقل تمام اعضا، محاسبهٔ بی‌پوشش‌ها | تفاوت مینیمال و انتخاب کوچک‌تر |
| prediction | مقدار/مجموعهٔ ثبت‌شده قبل از نمایش پاسخ ابزار | مقایسهٔ قبل/بعد و امکان اصلاح |
| classification/counterexample | ویژگی دقیق و شاهد نقض قابل بررسی | تعریف و نمونهٔ مقابل |
| minimumArgument | پوشش شاهد بالا + رد اندازه‌های کوچک‌تر/کران معتبر | صرف خروجی gamma یا ظاهر کوچک کافی نیست |
| route/number/choice | قرارداد دقیق نوع با دامنه و جواب‌های جایگزین | دلیل متناسب با خطای همان جزء |
| reflection | فقط الزام به بازبینی معیارها؛ بدون بررسی صحت متن آزاد | صریحاً «خودبازبینی توضیح»؛ نقد هم‌کلاسی اختیاری |

پاسخ ساخت‌یافتهٔ درست همهٔ معیارها + تأیید صریح خودبازبینیِ هر معیار، تکمیل فعالیت را
ممکن می‌کند. فیلد متن غیرخالی به‌تنهایی کافی نیست. یک checkbox عمومی «بلدم» جای همهٔ
شواهد را نمی‌گیرد. ارزیاب خودکار ادعای تشخیص درونی‌سازی ذهنی یا کیفیت متن ندارد.
بازبینی آموزشی انسانی برای ادعای انطباق طراحی باقی است؛ ارزیابی میدانی یادگیری ادعا نمی‌شود.

راهنمای نوعی پیش از جواب داده می‌شود؛ پاسخ نمونه دکمهٔ جدا دارد. نمایش جواب هیچ side effect
پیشرفت ندارد. در خروج، گونهٔ هم‌هدف با ساختار/پاسخ متفاوت ارائه شود؛ ابزار راهنما موجود
ولی شاهد انجام‌نشده با دیدن جواب تکمیل نشود. پاسخ غلط امکان بازگشت و بازسازی دارد.

## تعامل و ناوبری

در هر لحظه یک activity با هدف، معیار، صورت و ورودی لازم نمایش داده شود. آیندهٔ قفل‌شده
ورودی تعاملی ندارد. ناوبری درس و ساختار وضعیت/پیش‌نیاز را روشن می‌کند. پیش‌نیازها از داده
خوانده شوند؛ unit بعد با تمام requiredActivityIds از جمله خروج باز می‌شود. بازدید مجدد
هیچ پیشرفت قبلی را کاهش نمی‌دهد. پس از پاسخ درست بازخورد خوانا باقی بماند؛ «ادامه»
فوکوس را به عنوان فعالیت بعد می‌برد. motion off/reduced-motion هیچ تأخیر اجباری ندارد.

درس۲ بعد از خروج درس۱ باز می‌شود. پیش‌نیاز ناقص امکان مرور/کمک دارد؛ وابستگی به زمان،
رتبه، امتیاز یا نتیجهٔ تب دیگر ندارد. ۱۰۰٪ یعنی تکمیل مسیر، نه گواهی تسلط.

## پیشرفت جدید

شکل پیشنهادی فقط برای schemaVersion=2 و curriculumVersion=3:

```json
{
  "completedActivityIds": [],
  "passedUnitIds": [],
  "lastVisitedUnitId": "L1-Action"
}
```

passedUnitIds از پرچم‌ها و پیش‌نیازها دوباره محاسبه و اعتبارسنجی می‌شود؛ واحد قفل‌شده
مقصد معتبر نیست. درصد کل = مجموع وزن واحدهای پاس‌شده / مجموع وزن‌ها ×۱۰۰؛ نمایش
فارسی می‌تواند اعشار۱۲٫۵ داشته باشد. درسی = وزن واحدهای پاس‌شدهٔ همان درس / وزن آن درس.
پاسخ‌ها، پیش‌بینی اولیه، جدول‌ها، reflection، hint و score در این object یا envelope نیستند.

## تبدیل و آرشیو

envelope جاری schemaVersion=1/curriculumVersion=2 است. نسخهٔ جدید schemaVersion=2/
curriculumVersion=3 می‌خواهد؛ تغییر شکل پیشرفت بدون bump نسخهٔ ساختار ممنوع است.
فیلد teachingProgressArchive فقط یک snapshot معتبر curriculum=2 از سه فیلد پیشرفت قدیم
دارد؛ نسخه/کلیدهای اضافی یا پاسخ/امتیاز پذیرفته نمی‌شوند. آرشیو در درصد جدید دخالت ندارد.

۱. دادهٔ قبلی با validator و snapshot محتوای نسخهٔ خودش بررسی شود؛ نامعتبر حفظ و بازیابی
   خام ممکن باشد؛ دادهٔ نیمه‌معتبر بی‌صدا «ترمیم» یا پاک نشود.
۲. پیش‌نمایش درون‌صفحه‌ای: مسیر تازه متفاوت است؛ پیشرفت قبلی آرشیو می‌شود، تازه از صفر
   شروع می‌شود، خروجی قبلی در دسترس است. انصراف هیچ write ندارد.
۳. پس از تأیید، candidate کامل ساخته شود؛ schema/curriculum جدید و active progress خالی،
   آرشیو دقیق پیشرفت قبلی، تمام attempts/sessions/settings و نشان حذف بدون بازتفسیر حفظ شوند.
۴. اعتبارسنجی candidate، تطبیق revision و یک write؛ در quota/conflict هرگز نصف تبدیل ذخیره
   نشود. دادهٔ قبلی و خروجی بازیابی حفظ شوند. پیش از تأیید، سایر تب‌ها با دادهٔ قبلی کار کنند.
۵. اجرا روی نسخهٔ جدید دوباره آرشیو را عوض یا فعال را صفر نکند. reset آموزش فقط active
   progress را با تأیید صفر کند، نه آرشیو یا داده‌های سایر تب‌ها.

ورود بک‌آپ schema1/curriculum2 به نسخه۳: پیش‌نمایش آرشیو بدون اعتبار تازه؛ ادغام active
جدید صفر نمی‌شود. اگر دو آرشیو سازگارند union پرچم‌ها و prefix معتبر محاسبه شود؛ تعارض
غیرقابل اعتبارسنجی کل ورود را بدون write رد کند. نسخه۱ آموزش ابتدا طبق validator v1 و
قرارداد قدیمی به v2ِ صفر تبدیل می‌شود؛ از آن پیشرفت ساختگی ساخته نمی‌شود.
بک‌آپ schema2/curriculum3 فقط در نسخهٔ جدید مجاز است؛ downgrade به کد قدیم رد شود.
برخورد نشست‌ها، تقدم tombstone، محدودیت‌ها، شناسه‌ها، امتیاز و bankVersion از قرارداد
موجود پیروی می‌کنند؛ تغییر curriculum مجوز تغییر این قواعد نیست.
